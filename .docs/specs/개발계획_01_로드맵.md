## 2. Phase 1 — 전환 (2주, 07-27 ~ 08-07) · Sprint S1

- [ ] **DB 백업(D24)**: `pg_dump` 보관 + 스키마 rename으로 `public_backup`·`admin_backup` 생성(데이터 포함, 동결·읽기전용, 서비스 계정 권한 미부여)
- [ ] **Prisma 개정**: schema.prisma를 스펙 §6 구조로 전면 개편 — 코어 유지(User·Dog·Point·Shop·알림·DailyEntry) + 교육 도메인 신규, Walk·구 교육 테이블 drop, 마이그레이션 적용 + 시드

## 3. Phase 2 — 교육 코어 (6주, 08-10 ~ 09-18) · Sprint S2~S4

**목표**: 핵심 가치 흐름의 앞부분 완성 — **온보딩 → 맞춤 커리큘럼 → 레슨 루프(영상/자가체크/퀴즈) → 포인트 적립**.

### 범위 (IN)

- 온보딩: 강아지 프로필 + 설문 7문항(객관식·비분기, D17) + 룰 기반 태그 매칭(D9) + 레벨테스트(D5) + 데일리 목표 설정
- 커리큘럼 홈: 듀오링고식 경로 UI, 순차 잠금, 코스 동시 수강(D20)
- 레슨 플레이어: YouTube IFrame Player API, 95% 시청완료·배속 허용(D19, D6)
- 실습 자가체크(D2), 최종퀴즈(4지선다 3~5문항, D18)
- 포인트 적립: 레슨당 3회(P_watch/P_practice/P_quiz, D7) + 유닛/코스 완주 보너스(D20)
- 포인트 유효기간(D21): 적립+1년, FIFO 소멸, 소멸 배치 워커
- 정책설정(D16): 모든 정책값 관리자 설정(PolicyConfig) — 하드코딩 금지
- 관리자: 커리큘럼 CMS(코스/유닛/레슨/videoId/체크리스트/퀴즈), 설문·태그·가중치 운영

### 스프린트 개요

| # | 기간 | 주요 산출 |
|---|---|---|
| S2 | 08-10 ~ 08-21 | 온보딩(설문+태그 매칭+레벨테스트+데일리 목표), **커리큘럼 CMS**(콘텐츠팀 등록 개시) |
| S3 | 08-24 ~ 09-04 | 커리큘럼 홈(경로 UI), 레슨 플레이어(IFrame 95%), 자가체크, 순차 잠금 |
| S4 | 09-07 ~ 09-18 | 퀴즈, 포인트 적립 3종+완주 보너스, 유효기간 FIFO·소멸 배치, 정책설정 화면 |

### DoD

- 신규 유저가 온보딩 완주 → 추천 코스 수강 → 레슨 1개 완료 → 포인트 3회 적립까지 mobile-web에서 완결
- 관리자가 정책값(단가/통과 기준) 변경 시 즉시 반영
- `domain/education`·`domain/matching` 단위 테스트 85%+

## 4. Phase 3 — 수익화 (4주, 09-21 ~ 10-16) · Sprint S5~S6

**목표**: 포인트 이코노미의 뒷부분 완성 — **현금 충전(PG) → 포인트샵 소비 → 훈련사 Q&A**.

### 범위 (IN)

- 포인트 충전: PortOne(웹 채널) 결제 + webhook, 충전 패키지(정책 연동), 충전분/적립분 구분 원장(D3, D15 대비)
- 포인트샵 개편(D11): 실물 제휴 상품(기존 `order-fulfillment` 유지) + 훈련사 문의권 + 프리미엄 콘텐츠 잠금해제
- 훈련사 비동기 영상 Q&A(D4): 영상 업로드 → 문의권 차감 → 48h SLA → 초과 시 자동 환불, 보호자 별점
- admin-web TRAINER 롤(D13): RBAC, 답변 화면, 배정/모니터링
- 훈련사 월 정산(D12): 차감 포인트 × 정산 비율, 지급 내역
- 배지/학년: `grade.ts` 이수도 기반으로 교체, 코스/유닛 완주 배지(D8)
- 일상기록(보조, D1): 접종/산책유무/사진/자유기록 캘린더 — 포인트 미연동

### 스프린트 개요

| # | 기간 | 주요 산출 |
|---|---|---|
| S5 | 09-21 ~ 10-02 | PortOne 충전 + webhook, 포인트샵 개편(디지털 상품), 충전 내역 관리자 (추석 연휴 버퍼) |
| S6 | 10-05 ~ 10-16 | 훈련사 Q&A 전체 루프 + TRAINER 롤 + 정산, 배지/학년, 일상기록 |

### DoD

- 충전 → 문의권 구매 → Q&A 질문 → 훈련사 답변 → 평가 흐름 완결, SLA 초과 자동 환불 동작

## 10. 공통 운영 절차

### 10.1 환경 분리

| 환경 | 용도 | DB | 비고 |
|---|---|---|---|
| local | 개발자 PC | docker compose | MinIO로 S3 대체 |
| staging | 내부 QA | 114.207.113.140 (waggle_dev) | `public_backup`·`admin_backup` 동결 유지 |
| prod | 실서비스 | 복제 구성 (Phase 5) | |

### 10.2 릴리즈 체크리스트

모든 프로덕션 배포는 `engineering:deploy-checklist` 기준: CI 초록·리뷰 승인, DB 마이그레이션 무중단·롤백 가능, 기능 플래그, 롤백 조건 명시.

### 10.3 테스트 전략

| 계층 | 목표 커버리지 | 도구 |
|---|---|---|
| Domain (`education`/`matching`/`points`) | 85%+ | Vitest |
| Service/Repo | 70%+ | Vitest + Testcontainers |
| API E2E | 핵심 경로(레슨 루프·충전·Q&A) | Supertest |
| 웹 UI(모바일 뷰포트 + 관리자) | 주요 페이지 | Playwright |
| 부하 | 출시 직전 | k6 — **레슨 완료 동시 200건** (`infra/k6/lesson-completion.js`, 구 walk-completion 대체) |

RN 앱 E2E(Maestro)는 제거. shell은 WebView 스모크(로그인·푸시 수신·딥링크)만 수동+최소 자동화.

### 10.4 보안 점검 정기화
