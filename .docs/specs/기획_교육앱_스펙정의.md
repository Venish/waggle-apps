# Waggle 리뉴얼 — 강아지 교육 전문 앱 스펙 정의 (v0.3)

> 작성일: 2026-07-22 · 상태: 결정사항 D1~D22 확정, §10 잔여 이슈 6건
> v0.2: 모바일 아키텍처 확정(RN→모바일웹+shell, D14~15) · v0.3: 정책값·설문·퀴즈·수강·유효기간·콘텐츠 확정(D16~22)
> 기존 "산책/라이프로그 중심 + 부가 교육" → **"강아지 교육 기록 중심"** 앱으로 전면 피벗.

---

## 1. 비전 & 핵심 가치 흐름

**"듀오링고처럼, 우리 강아지에게 맞는 커리큘럼으로 매일 조금씩 교육하고 기록한다."**

```
온보딩(강아지 프로필 + 설문)
  → 맞춤 커리큘럼 제안
  → [레슨 루프] 교육영상 시청 → 실습(자가체크) → 최종퀴즈
  → 단계별 포인트 적립
  → 포인트 사용: 포인트샵 구매 / 훈련사 영상 문의 / 프리미엄 콘텐츠
```

- 핵심 자산: **강아지별 교육 이수 기록** (어떤 교육을, 언제, 어느 수준까지)
- 수익 모델: 포인트 현금 충전(PG) + 포인트샵 제휴 커머스 + (2차) 프리미엄 검토 서비스

| D17 | 설문 형식 | **전부 객관식, 비분기(분기 로직 없음), 단독 질문**으로 구성 |
| D18 | 퀴즈 형식 | **4지선다 객관식, 3~5문항** (문항 수·통과 기준 관리자 설정) |

## 4. 기능 정의

### 4.1 온보딩 (듀오링고식)

1. 강아지 프로필 등록: 이름, 견종, 생년월(월령), 성별, 중성화, 체중
2. 설문(D17): **전부 객관식, 비분기, 단독 질문** — 문항·선택지·태그는 관리자에서 편집 가능. 초안은 §4.1.1
3. **룰 기반 태그 매칭**: 설문 답변에 태그 부여 → 코스 태그와 매칭 점수 계산 → 점수순 커리큘럼 추천. 태그·가중치는 관리자 CMS에서 운영 조정
4. **레벨테스트(선택)**: 경험자용. 통과한 레벨 이하 레슨을 이수 처리하고 상위 단계부터 시작
5. 데일리 목표 설정: 1일 학습량(예: 레슨 1개) + 리마인드 푸시 시간대

#### 4.1.1 설문 문항 초안 (v0.1 — 7문항, 관리자에서 수정 가능)

월령·견종은 프로필에서 자동 태그화(puppy/adolescent/adult/senior)하므로 설문에서 제외.

| # | 질문 | 선택지 | 선택 | 매칭 태그 예 |
|---|---|---|---|---|
| 1 | 강아지 훈련 경험이 있으신가요? | 처음이에요 / 영상 보고 독학해봤어요 / 이전 반려견을 키워봤어요 / 전문 교육을 받아본 적 있어요 | 단일 | exp_none, exp_self, exp_prev, exp_pro |
| 2 | 고치고 싶은 행동이 있나요? | 짖음 / 분리불안 / 배변 실수 / 입질·물기 / 산책 줄당김 / 사람·타견 경계 / 없음 | **복수** | prob_bark, prob_sep, prob_potty, prob_bite, prob_leash, prob_social |
| 3 | 교육의 주된 목표는 무엇인가요? | 기본 예절 익히기 / 문제행동 교정 / 유대감·놀이 / 심화 훈련 도전 | 단일 | goal_basic, goal_fix, goal_bond, goal_adv |
| 4 | 하루에 얼마나 교육할 수 있나요? | 5분 / 10분 / 20분 이상 | 단일 | (데일리 목표 기본값) |
| 5 | 어떤 환경에서 지내나요? | 아파트·빌라 / 마당 있는 주택 | 단일 | env_apt(짖음·실내예절 가중), env_house |
| 6 | 다른 강아지나 사람을 만나면 어떤가요? | 편안해해요 / 너무 흥분해요 / 무서워해요 / 으르렁·공격적이에요 | 단일 | soc_ok, soc_excite, soc_fear, soc_aggr |
| 7 | 우리 강아지가 가장 좋아하는 보상은? | 간식 / 장난감 / 칭찬·스킨십 / 잘 모르겠어요 | 단일 | (훈련 팁 개인화용) |

### 4.2 커리큘럼 구조

```
Course (코스: 예. 퍼피 기본예절, 분리불안 개선)
└─ Unit (유닛: 주제 묶음)
   └─ Lesson (레슨) = 영상 시청 → 실습(자가체크) → 최종퀴즈
```

- 진행 방식: **순차 잠금**. 레슨 완료(퀴즈 통과) 시 다음 레슨 해제
- 레슨 완료 정의: 시청완료 AND 실습성공 AND 퀴즈통과
- **코스 동시 수강 허용** (D20) — 잠금은 코스 내에서만 적용
- 초기 라인업(D22): 6~7개 코스, 약 100개 레슨

### 4.3 영상 시청

- YouTube unlisted 영상을 **IFrame Player API**로 임베드
- 시청완료 판정(D19): Player API 진도 이벤트 기반 **95% 이상 시청, 배속 허용** — 클라이언트 판정 + 서버 기록
- 관리자 CMS에는 YouTube videoId만 등록 (원본 파일 관리 없음)

### 4.4 실습 (MVP: 자가체크)

- 레슨별 실습 체크리스트(예: "'앉아' 지시에 3회 중 2회 성공") 제시 → 보호자 자가 체크 시 실습 성공 처리
- 어뷰징 완화: 실습 포인트는 소액으로 설계, 동일 레슨 반복 지급 없음
- **(2차/프리미엄)** 실습 영상 업로드 → 훈련사 검토·피드백 후 통과 판정. S3 업로드 + `video-postprocess` 큐 재활용

### 4.5 최종퀴즈

- **4지선다 객관식, 3~5문항** (D18). 문항 수·통과 기준(예: 80%)은 관리자 설정
- 재시도 무제한, 포인트는 최초 통과 1회만
- 통과 시 다음 레슨 잠금 해제

### 4.6 포인트

**적립** (레슨당 각 최초 1회):

| 이벤트 | 지급 |
|---|---|
| 영상 시청완료 | P_watch |
| 실습 성공 | P_practice |
| 퀴즈 통과 | P_quiz |
| 유닛/코스 완주 보너스 | 제공 (D20, 금액은 관리자 설정) |

**충전**: PG(카드/간편결제)로 포인트 패키지 구매. 충전분/적립분 구분 원장 관리(정산·환불·IAP 대응 대비).

**사용**: 포인트샵 실물 구매 / 훈련사 문의권 / 프리미엄 콘텐츠 잠금해제

- 기존 원칙 유지: 적립/차감은 단일 트랜잭션 (SELECT FOR UPDATE → PointLedger insert → PointWallet update), `point-settler` 큐 경유
- **유효기간(D21): 적립일로부터 1년.** 선입선출(오래된 포인트부터) 소멸, 소멸 30일/7일 전 푸시 알림. 소멸 배치는 worker 큐로 처리
- 모든 단가·보너스·가격은 관리자 정책 설정(D16)에서 운영 조정 — 초기값은 런칭 전 세팅
- 환불 정책: 미확정(§10)

### 4.7 훈련사 영상 Q&A (비동기)

1. 보호자: 문제 행동 영상(≤N분) + 질문 텍스트 업로드 → 문의권(포인트) 차감
2. 배정: 관리자 수동 배정 or 분야 태그 기반 자동 배정 — 미확정(§10)
3. 훈련사: admin-web에서 **48시간 내** 텍스트/영상 답변
4. SLA 초과 시 자동 환불(포인트 복구)
5. 보호자 평가(별점) — 훈련사 노출 순위에 반영(2차)

### 4.8 게이미피케이션

- **데일리 목표 + 리마인드 푸시**: 목표 미달성 시 설정 시간대 푸시 (`notification-dispatcher`)
- **배지/레벨(강아지 학년)**: 기존 "월령→학년"을 **"교육 이수도→학년"**으로 전환 (`packages/domain/dogs/grade.ts` 로직 교체). 코스/유닛 완주 배지
- 스트릭, 리그/랭킹: 2차

### 4.9 일상기록 (보조)

- 접종 기록, 산책 유무(단순 체크), 사진 업로드, 자유 텍스트 기록
- 포인트 미연동, 캘린더 뷰 제공. GPS/경로 트래킹 없음

### 4.10 포인트샵

- 상품 유형: ① 실물 제휴 상품(배송 — 기존 `order-fulfillment` 큐 유지) ② 훈련사 문의권 ③ 프리미엄 콘텐츠 잠금해제
- 기존 포인트샵 기획(userRequirement_app_포인트샵*) 대부분 유지, 디지털 상품 유형 추가

### 4.11 관리자 (admin-web)

- **커리큘럼 CMS**: Course/Unit/Lesson CRUD, YouTube videoId 등록, 실습 체크리스트·퀴즈 문항 편집, 게시/버전 관리
- **정책 설정(D16)**: 포인트 단가(시청/실습/퀴즈), 유닛·코스 완주 보너스, 충전 패키지 가격(웹/IAP 각각), 문의권 가격, 정산 비율, 퀴즈 문항 수·통과 기준, 일일 적립 상한 — 변경 이력 AuditLog 기록
- **매칭 운영**: 설문 문항·선택지·태그·가중치 관리
- **훈련사 관리**: 계정(TRAINER 롤), 분야 태그, Q&A 배정/모니터링, 월 정산(포인트→현금, 지급 내역)
- **포인트/결제**: 충전 내역(PG), 원장 조회, 수동 조정(AuditLog 필수)
- 기존 유지: 회원, 주문/배송, 배너, AuditLog

## 5. 제거/변경되는 기존 기능

| 기존 | 처리 |

## 6. 데이터 모델 변경 개요 (상세는 아키텍처_03 개정 시)

스키마 구성(D24): `public_backup`·`admin_backup`(스냅샷·동결) / `public`(앱 도메인 전체) / `admin`(관리 전용) — 기존 2스키마 체계 유지, 내용만 개편.

**유지 (public)**: `User`, `Dog`, `Breed`, `PointWallet`/`PointLedger`, Shop/Order 계열, 알림, `DailyEntry`(일상기록). `Walk`/`WalkPhoto` 및 7월에 추가된 구 교육 테이블(Course/Quiz/CourseProgress 등)은 backup 후 drop

**신규 (public, 교육 도메인)**: `Course`, `Unit`, `Lesson`, `LessonStep`(video/practice/quiz), `PracticeChecklist`, `Quiz`, `QuizQuestion`, `QuizAttempt`, `Enrollment`(강아지-코스), `LessonProgress`(강아지-레슨, 단계별 완료·포인트지급 플래그), `SurveyQuestion`/`SurveyAnswer`, `Tag`/`CourseTag`/`AnswerTag`, `LevelTest`/`LevelTestAttempt`, `Trainer`(프로필·분야태그), `Inquiry`(Q&A: 영상, 질문, 답변, 상태, SLA), `PointRecharge`(PG/IAP 결제), `DailyGoal`, `Badge`/`DogBadge`

**admin (유지 + 신규)**: 유지 — `Admin`(계정, TRAINER 롤 추가), `AuditLog`, `Banner` / 신규 — `TrainerSettlement`(월 정산), `PolicyConfig`(D16 정책값 key-value + 변경 이력)

**포인트 유효기간(D21) 반영**: `PointLedger` 적립 건에 `expiresAt`(적립+1년) 추가, 차감 시 선입선출 소진, 만료 배치(worker)가 소멸 차감 기록 생성

**제거**: `Walk` 및 산책 파생 테이블, 공간 인덱스(`walk_path_gix`). PostGIS 확장 자체 제거 여부는 마이그레이션 시 결정

**변경**: `PointLedger`에 적립원천 구분(earn_education / recharge / spend_shop / spend_inquiry / refund 등), 진도는 User가 아닌 **Dog 기준** (한 계정 다견 지원)

## 7. 시스템 영향 요약

- **mobile-api**: walk 모듈 제거 → education / curriculum / quiz / inquiry / recharge(PG webhook) 모듈 신설
- **admin-api**: CMS, 훈련사 롤(RBAC: ADMIN/TRAINER), 배정, 정산 API 추가
- **worker 큐 개편**: `lesson-evaluator`(구 mission-evaluator), `notification-dispatcher`(유지), `video-postprocess`(Q&A 영상만), `order-fulfillment`(유지), `point-settler`(유지 + recharge/inquiry 이벤트 추가), `inquiry-sla-watcher`(신규: 48h 감시·자동환불)
- **모바일 (D14, RN 폐기)**:
  - `apps/mobile-web` (신규, Next.js): 커리큘럼 홈(듀오링고식 경로 UI), YouTube iframe 플레이어, 퀴즈, Q&A 업로드(file input capture), 일상기록, 포인트샵. admin-web과 Tailwind + `@waggle/design-tokens` 공유
  - `apps/android-shell` (신규, Kotlin): WebView 래퍼 + FCM 푸시 + 딥링크 → Play 스토어 테스트 출시
  - `apps/ios-shell` (2단계, Swift): WKWebView + APNs + 네이티브 탭바·알림설정 (심사 4.2 최소기능성 대응) → App Store 출시
  - `apps/mobile-app`(RN), `packages/native-walk`, `apps/poc-walk` 제거
  - 향후 위치기반 커뮤니티: **네이버맵 JS API v3**를 mobile-web에서 직접 사용 (네이티브 SDK 브릿지 불필요)
- **PG 연동**: PortOne (기존 결정 유지) — 웹 포인트 충전 결제 + webhook 처리. iOS/Android 앱 내 충전은 IAP(채널별 가격 차등, D15)
