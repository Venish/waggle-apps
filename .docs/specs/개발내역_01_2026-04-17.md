## 2. 빌드 시스템 픽스

### 문제
- `@waggle/prisma` 패키지의 `main`이 `.ts` 파일을 직접 가리켜 런타임 오류 발생
- `nest build`가 `tsbuildinfo` 캐시 문제로 `dist/` 없이 exit 0 반환
- `@fastify/static` v9가 Fastify 4에 호환되지 않아 앱 크래시

### 해결
- `packages/prisma/package.json`: `"main": "./dist/index.js"`, `"build": "tsc -p tsconfig.json"` 추가
- `apps/mobile-api/package.json` + `apps/admin-api/package.json` 빌드 스크립트: `"build": "rm -f tsconfig.tsbuildinfo && nest build"`
- `@fastify/static@6` 으로 다운그레이드 (Fastify 4 호환 버전)
- `apps/mobile-api/tsconfig.json` + `apps/admin-api/tsconfig.json`: `"declaration": false, "declarationMap": false` 추가 (Prisma `$extends` 복합 타입 오류 방지)

### 산책 흐름
```

  → Walk 생성 (status: IN_PROGRESS)
  → In-memory GPS 버퍼 초기화

PUT /walks/:id/gps (update, 주기적 호출)
  → GPS 포인트 버퍼에 추가
  → validateGpsTrack() 실행 → 현재 거리 반환
```

### PostGIS LINESTRING 저장 방법
```typescript
// Prisma.sql + Prisma.raw 조합으로 SQL Injection 방지
// linestring 값은 내부 계산 결과(GPS 좌표)이므로 Prisma.raw 사용 허용
const pathGeomFragment = linestring
  ? Prisma.sql`ST_GeomFromText('LINESTRING(${Prisma.raw(linestring)})', 4326)::geography`
  : Prisma.sql`NULL`;
```

### BullMQ Redis 폴백 (개발 환경)
```typescript
try {
  await queue.add('walk.completed', { ... });
} catch {
  // Redis 미연결 시 동기 직접 적립

}
```

### 핵심 로직

**포인트 적립 조건**
- 퀴즈 없는 강의: `watchedS ≥ durationS` 달성 시 → `PointReason.LESSON_REWARD`
- 퀴즈 있는 강의: 퀴즈 통과(`correctCount ≥ passScore`) 시 → `PointReason.LESSON_REWARD`

**중복 적립 방지**
- `LessonProgress.pointAwarded` 플래그 사용
- 퀴즈 재제출 시 `quizPassed` true → false 다운그레이드 방지 (`...(passed && { quizPassed: true })`)

**수강 진도 자동 갱신**
```
enrollment.progress = round(완료된 강의 수 / 전체 강의 수 × 100)
progress = 100 → enrollment.completedAt 자동 기록
```

**HLS presigned URL**
- S3 `GetObjectCommand` (업로드의 `PutObjectCommand`와 다름), `expiresIn: 60`
- `videoUrl`이 full URL일 경우 pathname에서 key 추출

**미션 이벤트 발행**
- 강의 완료 시 `mission-evaluator` 큐에 `education.completed` 잡 발행
- Redis 미연결 시 예외 catch 후 skip (BullMQ 폴백 없이 무시)

```

→ Order(status=PAID) + PointLedger(delta=-N, reason=ORDER_USE)
→ 즉시 완료

→ SELECT FOR UPDATE (stock) → 재고 차감
→ Order(status=PENDING)
→ POST /v1/orders/webhook (@Public, HMAC-SHA256 서명 검증)
→ imp_uid/status='paid' 수신 → PAID + PointLedger
→ 취소/실패 시 → 재고 복구 + CANCELLED/FAILED
```

**FCM 발송 플로우**

```
[모든 모듈에서] notificationsService.dispatch(data, opts?)
  → queue.add('send', data, { delay? })
  → NotificationDispatcherProcessor.process(job)
    → Device.findMany (userId 기준 pushToken 수집)
    → FcmService.send (sendEachForMulticast)
    → Notification.create (DB 기록)
```

**접종 알림 자동 예약**

```
POST /v1/dogs/:dogId/vaccinations { nextDueAt: '2026-05-15' }
→ D-7 delayed job: delay = nextDueAt-7days - now
→ D-1 delayed job: delay = nextDueAt-1day - now
→ 각각 kind=VACCINE_DUE 알림 발송 (Redis 없으면 DB 직접 기록)
```
