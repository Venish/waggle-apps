## 2. 각 도메인 폴더 내 3종 MD 필수 작성 기준 (Stage 2 검수 체크포인트)

모든 도메인 폴더(`01 ~ 10`)는 아래 3개 파일을 한 세트로 작성하며, **데이터(PostgreSQL 18) ➔ 로직(ACID/권한) ➔ 화면(Clean Neo-Pop / Atlas 동선)**이 1:1로 일치해야 검수를 통과한다.

| 파일명 | 필수 포함 디테일 (검수 기준) |
| :--- | :--- |
| **`01_table.md`**<br/>*(PostgreSQL 18 물리 테이블)* | • **단일 소유(Single Owner) & 7대 감사 컬럼 필수**: 테이블명(`snake_case`), 컬럼 물리 타입(`BIGINT` 원/포인트 정수, `REAL/DOUBLE PRECISION` 금지), `NULL`/기본값 + **전 `MUTABLE` 테이블 7대 감사 컬럼 필수** (`APPEND_ONLY` 화이트리스트 7종만 예외)<br/>• **무결성 & 소프트 삭제 유니크**: 복합 인덱스, PostgreSQL 네이티브 부분 유니크 인덱스(`WHERE is_deleted = false`) 제약<br/>• **참조 삭제 차단(`CanDelete`)**: `ON DELETE CASCADE` 금지(`RESTRICT`), 하위 데이터 존재 시 삭제 차단 대상 테이블 명시 |
| **`02_feature.md`**<br/>*(기능 · 트랜잭션 · API)* | • **기능 ID별(`예: D04-F01`) CRUD 상세**: 입력 `Zod` 검증, 순수 도메인 계산식(`packages/domain` 7종 이식 규칙), `PolicyConfig` 동적 정책 키<br/>• **단일 ACID 트랜잭션 & 멱등키**: 결제/포인트 원장·주문·레슨 완료 보상을 `db.transaction` + `UNIQUE` 멱등키로 원자적 처리<br/>• **권한 & 진입점 구분**: `03_actions/{web,admin}` vs 예외 `app/api/*`(웹훅/OAuth/업로드/Cloud Scheduler `/api/cron/*`), `Repo / Service / Action` 시그니처 |
| **`03_screen.md`**<br/>*(화면 · 메뉴 · 디자인 동선)* | • **메뉴 위치 & 디자인 시스템**: 소속 Route Group(`(www)` / `(mobile)` / `(admin)`), URL 라우트, 적용 SSOT(`DESIGN_WEB.md` vs `DESIGN_ADMIN.md`), 노출 권한(`USER`/`ADMIN`/`TRAINER`)<br/>• **화면 영역별 구성**: 기존 `.scratch/references/waggle_apps-main/` 화면 대비 리뉴얼 레이아웃·컴포넌트·모든 입출력 필드(**`01_table.md`의 `table.column` 영문 키 1:1 매칭 필수**), 유니코드 이모지 0건(`lucide-react` 전용), 선언된 `rem` 토큰 전용<br/>• **사용자 작업 동선 (`Step-by-Step User Flow` 3종 필수)**: ① 기본 업무 동선 ② 타 도메인 연계 동선 ③ 예외·차단 동선(`useAlert`, 포커스 이동, 권한/삭제 차단) |
